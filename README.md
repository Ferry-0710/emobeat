# EmoBeat · 基于人脸情绪识别的歌曲推荐系统

> 纯前端（HTML5 + CSS3 + JavaScript + Vue 3）实现。人脸检测、表情识别、音频情绪分析、推荐排序
> **全部在浏览器本地完成**，不上传任何图像或音频。

---

## 快速运行

模型权重通过 `fetch` 加载，**必须用 HTTP 方式访问**（直接双击 index.html 会被浏览器拦截）。

```bash
# 方式一：Windows 双击 start.bat
# 方式二：手动
python -m http.server 8080
# 然后浏览器打开 http://localhost:8080
```

首次打开会自动加载本地 face-api 模型（约 0.5 MB，已随项目附带），加载完成后自动载入一张演示人脸并生成推荐。

> 调试小技巧：控制台可直接访问 `__app`（Vue 实例），例如 `__app.rec`、`__app.cur`、`__app.doRecommend()`。

## 算法要点

### 1. 人脸情绪识别

- **检测**：TinyFaceDetector（SSD-MobileNetV1 变体，单阶段锚框回归），输入 160/224/320 可切换。
  单帧图片若在低精度下漏检，会自动升到 320 重试一次（竖幅人像在小输入下漏检率偏高，实测 21 张演示人像中 11 张需要升档）；实时模式保持所选精度以保住帧率。
- **分类**：FaceExpressionNet，64×64 灰度人脸 → 7 类 Softmax（FER2013 训练）。
- **平滑**：`p̂_t = (1-α)·p̂_{t-1} + α·p_t`，α 可选 0.15/0.35/0.6；主标签需连续 3 帧一致才提交（滞后判决）。
- **投影**：7 类概率按 `p^1.15` 加权投影到 Thayer 空间，得到连续 (V, A, R)。

### 2. 旋律情绪识别

- **STFT**：Hann 窗，N=2048，H=512，22.05 kHz → 86.1 帧/秒。
- **速度**：半波整流谱通量 → onset 包络自相关 → 对数正态节拍先验 + {τ/2, τ, 2τ} 倍频修正 +
  **半速纠偏**（慢读法 < 105 BPM 且 2 倍读法的自相关强度 > 0.62 倍时采用快读法）+ 抛物线插值。
- **节奏密度**：相对阈值峰值拾取，统计强起始点/秒。
- **频率高低**：谱质心、高频能量比（取中位数抗打击乐干扰）。
- **调性**：HPCP（逐帧归一化的谱峰色度）+ Krumhansl–Schmuckler 轮廓相关 + 主音显著性 + 三度音判调式。
- **映射**：V/A/R/和声熵 → 7 类情绪原型加权欧氏距离 → Softmax。

实测（15 首标注曲库）：情绪分类 **12/15 (80%)**，调式 **14/15 (93%)**，节拍平均相对误差 **0.1%**，单曲 40 秒音频分析 **~100 ms**。

> 说明：这一批曲目刻意包含"半音簇 / 失谐"等极端样本（用于区分厌恶与恐惧），其调性本身是模糊的，
> 因此拉低了总体准确率；对调性明确的曲目（大调/自然小调）调式判断稳定正确。

### 3. 推荐

```
sim_space = exp(-d²(target, candidate) / 0.16)     # 距离只用效价 V 与唤醒 A
sim_emo   = cos(p_face, p_music)
score     = 0.58·sim_space + 0.32·sim_emo
            × (0.72 + 0.28·confidence) × (recent ? 0.55 : 1)
MMR       = argmax [ λ·score - (1-λ)·max sim(c, s) ],  λ = 0.78
```

策略通过变换目标坐标实现：匹配（不变）、舒缓（降唤醒升效价）、提振（高唤醒正向）。

## 数据来源与版权

- **演示人脸**：21 张由 AI 生成的写实人像（7 种情绪 × 3 位不同人物），不对应真实人物，仅用于功能演示。
- **本地曲库**：`scripts/gen_music.py` 程序化合成的免版权曲目，不涉及第三方版权。
- **在线检索**：iTunes Search API（无需密钥，`Access-Control-Allow-Origin: *`），仅播放其官方 30 秒试听片段。
- **模型**：face-api.js 预训练权重（MIT）。

## 自测覆盖

以下路径均已用无头浏览器（Chrome + swiftshader 软渲染）端到端跑通，控制台零报错：

| 路径 | 验证方式 | 结果 |
|---|---|---|
| 图片上传 | 21 张演示人脸逐张识别（含自动升档） | **21/21** 主标签正确（11 张由 224 自动升到 320 才检出） |
| 七类情绪 → 推荐 | 每类取一张演示脸，看推荐首位 | 7/7 首位命中同类曲目（如惊讶 → Bolt from Blue 77%） |
| 视频文件 | 640×480 / 3 s 人像视频循环播放 | 首帧出情绪 **133 ms**，`FACES 1`、稳定 14 帧、置信度 1.0 |
| 图片模式拖入视频 | 模拟 `drop` 事件 | 自动切到视频源并开始检测 |
| 实时摄像头 | Chrome 假设备（100 帧 Y4M 人像） | 授权到出情绪 **779 ms**，稳定 13 帧，置信度 1.0 |
| 屏幕共享 | 捕获 1920×1080 整屏（画面内有大尺寸人脸） | 正确识别为「惊讶」，稳定 61 帧，**20 FPS / 单帧 20 ms** |
| 本地曲库 | 15 首重分析 | 约 1.5 s（100 ms/首），推荐首位与标注一致 |
| 在线曲库 | iTunes 检索 → 入池分析 | 14 条结果，试听音频本地分析 251 ms |
| 播放器 | 播放 / 下一首 / 上一首 | 时长 30.04 s，切歌正确 |

> 性能分两档：真实 GPU（有头浏览器，WebGL 后端）单帧 **20 ms**、稳定 **20 FPS**；
> 无头 Chrome + swiftshader 软渲染（纯 CPU）单帧 143～161 ms，约 5～9 FPS。瓶颈完全在推理而非 UI。

## 已知限制

- 恐惧 ↔ 厌恶在音乐情绪上天然接近（低效价 + 高半音化），是主要混淆来源。
- 自相关节拍估计存在倍频歧义（170 BPM 与 85 BPM 的听觉感受都成立）。已加半速纠偏（当前曲库误差 0.1%），
  但**真正**以半速律动写作的曲子（每两拍一击）仍可能被翻倍判读——这一歧义无法只靠自相关消除。
- 侧脸、强遮挡、逆光会显著降低人脸检测成功率；竖幅人像在 224 输入下漏检率偏高，程序会自动升到 320 重试，代价是单帧耗时翻倍。
- 摄像头需要 `https` 或 `localhost` 环境（浏览器安全策略）。
