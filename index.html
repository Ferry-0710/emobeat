一、人脸情绪识别算法（本地）

1. 人脸检测 —— TinyFaceDetector

TinyFaceDetector 是 SSD (Single Shot MultiBox Detector) 的极轻量变体，主干为 MobileNetV1 的深度可分离卷积， 在 WIDER FACE 上训练。它是"单阶段检测器"：一次前向传播同时回归边界框位置与置信度，无需 RPN 候选区域，因此速度极快。

// 锚框回归 + 分类 (每个特征图位置 k 个 anchor)
tx = (x − xa) / wa,   ty = (y − ya) / ha
tw = log(w / wa),   th = log(h / ha)
// 损失 = 分类交叉熵 + 平滑 L1 定位损失
L = (1/N)·Σ Lcls(p, p*) + λ·(1/Npos)·Σ p*·Lreg(t, t*)

输入帧先缩放到 160 / 224 / 320（可切换）后推理，输出人脸框与置信度。实测单帧 {{ perf.total }} ms（本机实测，含检测与表情分类）。因为检测是最耗时环节，程序采用 帧级节流（丢帧策略）与 可选关键点跳过来保证 20+ FPS 的实时体验。

补充：单帧图片识别没有帧率压力，若在 160/224 下漏检，程序会自动升到 320 再试一次 （竖幅人像、脸占比偏小的照片在小输入下容易漏检）；实时模式则保持所选精度，避免拖慢帧率。

2. 表情分类 —— FaceExpressionNet

对人脸框裁剪并缩放到 64×64 灰度图，送入 8 层卷积网络（Conv→BN→ReLU→MaxPool）+ 全连接，最后 Softmax 输出 7 类概率：neutral / happy / sad / angry / fearful / disgusted / surprised。训练集为 FER2013（35,887 张 48×48 灰度人脸）。

pk = ezk / Σj=1..7 ezj   // 7 类表情概率
// 交叉熵损失
L = −Σk yk · log pk

3. 时序平滑与稳定判决

单帧预测会在相邻类别间抖动。这里采用 指数滑动平均 (EMA) 做概率平滑，再加 滞后判决 (hysteresis)： 只有连续 N 帧（默认 3 帧）都判为同一类，才真正切换最终标签，避免"脸部一歪就换歌"。

p̂t(k) = (1 − α)·p̂t−1(k) + α·pt(k),   α ∈ [0.15, 0.6]
// 归一化，保证和为 1
p̂t(k) ← p̂t(k) / Σj p̂t(j)
labelt = argmaxk p̂t(k)  (需连续 hold=3 帧才提交)
为什么高效：检测与分类共享同一次前向；EMA 只是 7 维向量运算（O(7)）； 概率平滑后可以直接抑制低置信度抖动，因此无需昂贵的多模型集成，也不必每帧都做检测。

4. 从表情到情绪坐标

把 7 类概率按权重投影到 Thayer 环状空间（效价 V / 唤醒 A / 粗糙 R），得到连续的情绪向量， 避免"离散标签"造成的推荐跳变：

V = Σk wk·Vk / Σk wk,   wk = p̂(k)1.15
同理得到 A、R (幂次 1.15 用于放大主情绪权重)

二、旋律 / 曲调情绪识别算法

目标：从音频本身提取"快慢、节奏密度、音高高低、调式明暗、失真程度"等客观特征， 再映射到与情绪识别相同的 V-A-R 空间。

1. 分帧与频谱 —— STFT

X(m, k) = Σn=0..N−1 x(n + mH) · w(n) · e−j2πkn/N
N = 2048 (帧长), H = 512 (帧移), w(n) = 0.5 − 0.5·cos(2πn/(N−1))  Hann 窗
采样率 22050 Hz → 帧率 86.1 帧/秒, 频率分辨率 10.8 Hz

FFT 使用 Cooley–Tukey 基 2 迭代算法，复杂度 O(N log N)；40 秒音频约 1700 帧，全流程 < 150 ms。

2. 快慢 —— 节拍估计（自相关 + 倍频修正）

先用半波整流谱通量得到起始强度包络（onset strength envelope），再对包络做自相关， 相关峰的滞后量对应节拍周期：

SF(m) = Σk max(0, |X(m,k)| − |X(m−1,k)|)  谱通量
r(τ) = Σm Ŝ(m)·Ŝ(m+τ) / (M − τ)  自相关
BPM* = argmaxτ r(τ) · P(60·fs/τ),   P(bpm) = exp(−½(log₂(bpm/115)/1.05)²)
// P 为对数正态先验: 人类更倾向于把节拍感知在 80–160 BPM 附近

自相关法最常见的问题是倍频错误（把 170 BPM 听成 85）。这里对候选滞后 {τ/2, τ, 2τ} 联合打分， 并优先选择落在常规区间的解；再加一道半速纠偏：当慢读法 < 105 BPM、其 2 倍读法落在 110–190 且自相关强度与慢读法相当（> 0.62 倍）时，采用快读法——因为"每拍一击 + 密集八分音符" 的织体在 2 拍周期上同样会出峰。抒情慢歌的八分音符层次相关值通常只有 0.1–0.2 倍，不会被误翻倍。 最后用抛物线插值精修亚帧精度。当前曲库平均相对误差 {{ validation ? (validation.bpmMae*100).toFixed(1) : '—' }}%。

3. 节奏密度 —— 起始点检测

onset 判据: Ŝ(m) > 1.5·mean(Ŝ)  且为局部极大
强起始: Ŝ(m) > 0.28·max(Ŝ)  → 密度 D = 强起始数 / 时长 (个/秒)

密度 D 直接反映"节奏是否密集"（例如 4/4 摇滚每拍底鼓 + 八分音符踩镲，D 可达 8/s；抒情钢琴 D ≈ 1/s）， 是唤醒度最重要的指标之一。

4. 频率高低 —— 谱质心与高频能量比

C = Σk fk·|X(m,k)| / Σk |X(m,k)|  谱质心 = 音色亮度
HF = Σf>4kHz |X| / Σf |X|  失真/噪声感 (取中位数抗打击乐干扰)

5. 调式明暗 —— HPCP 色度 + Krumhansl–Schmuckler 调性识别

把每个谱峰按频率映射到 12 个音高类（midi = 69 + 12·log₂(f/440)），得到 12 维色度向量。 关键细节：逐帧归一化后再累加，否则一个低音音头就会霸占整个色度。

HPCP[c] += Σk: pc(k)=c |X(k)| · tonality(m),   tonality = 1 − 8·flatness
// 用 Krumhansl–Schmuckler 轮廓做相关, 找最匹配的主音与调式
ρ(r, mode) = corr( rotate(HPCP, r), KKmode ) + 0.26·HPCP[r] + 0.10·BassHPCP[r]

KK 大调/小调轮廓来自 1990 年 Krumhansl 的听知觉实验（主音、三音、五音的稳定性排序）。 由于关系大小调共享同一音集，这里额外引入主音显著性与低音声部色度来消歧； 再用三度音（大三度 vs 小三度）的能量差直接判定调式。当前曲库调式识别 {{ validation ? (validation.keyAcc*100).toFixed(0) : '—' }}%。

6. 四维特征 → 七类情绪

把上面所有指标压缩成 4 个语义维度，再用加权欧氏距离 + Softmax（即最小距离分类器）对 7 个情绪原型打分：

V = 0.5 + s·(0.18 + 0.09·Smode)·Ckey + 0.10·2(Cn − 0.40) − 0.10·max(0, R − 0.60)
  s = +1 (大调) / −1 (小调); Ckey = 调式置信度 (证据弱时向 0.5 收缩)
A = 0.34·norm(bpm,58,172) + 0.20·norm(D,0.6,6.5) + 0.16·norm(rms,.15,.42)
    + 0.14·norm(flux,.09,.21) + 0.16·pulseClarity
R = 0.42·norm(HF) + 0.30·norm(ZCR) + 0.18·norm(flux) + 0.10·norm(flatness)

de = 1.30(V−Ve)² + 1.15(A−Ae)² + 0.50(R−Re)²
P(e) = softmax(−de / 0.05)

三、推荐算法与推荐策略

1. 统一情绪空间

人脸情绪与音乐情绪都投影到同一个 Thayer 环状模型（Russell 1980 的 circumplex 变体）： 横轴 V（效价：不愉快 ↔ 愉快），纵轴 A（唤醒：平静 ↔ 激动）。这样"人的情绪"与"音乐的情绪"可以直接比距离。

{{ emo(k).cn }} ○ 虚线 = 当前推荐目标坐标

2. 推荐策略（心情调节理论）

① 情绪匹配 match

目标 = 当前情绪。适用于"想被理解"的场景：难过时听慢速小调更能共情。 这是 情绪一致性 (mood congruence) 策略。

② 舒缓调节 soothe

保留共鸣但降低唤醒、抬高效价：V′ = 0.55 + 0.42V，A′ = 0.18 + 0.30A。 即"先接住情绪，再轻轻拉出来"。

③ 提振精神 energize

向高唤醒 + 正向迁移：V′ = 0.62 + 0.36V，A′ = 0.62 + 0.32A。适用于疲惫、低落时需要"推一把"。

3. 打分函数（内容推荐 + 情绪分布相似）

simspace(c) = exp( − d²(target, c) / 0.16 )  # d² 只用 V、A (人脸与音频的 R 量纲不同)
simemo(c) = cos( pface, pmusic(c) )  # 7 维情绪分布余弦
score(c) = 0.58·simspace + 0.32·simemo
        × (0.72 + 0.28·confidencec)  # 元数据可信度惩罚
        × (recent ? 0.55 : 1)  # 最近播放降权

4. 多样性重排 —— MMR

纯按分数排序会出现"6 首全是 126BPM 的大调流行"。用 Maximal Marginal Relevance （Carbonell & Goldstein, 1998）在相关性与多样性之间折中：

MMR = argmaxc∈R\S [ λ·score(c) − (1−λ)·maxs∈S sim(c, s) ],   λ = 0.78

λ 越大越偏重相关性；这里取 0.78，既保证第一首最贴合情绪，也保证后面几首在 BPM / 调式上有变化。

5. 推荐解释

每条推荐都会给出"为什么"：速度 / 调性 / 音色三个最直观的证据 + 与目标坐标的偏差方向。 例如 慢速 66 BPM、小调(A minor)、暗色音色 · 与目标情绪坐标高度重合。

快速开始

必须通过 HTTP 打开：模型文件需要用 fetch 加载，直接双击 index.html（file://）会被浏览器安全策略拦截。 在项目目录执行 python -m http.server 8080，然后访问 http://localhost:8080。 Windows 可直接双击 start.bat。

四种获取人脸的方式

  1. 图片：点"选择图片"上传本地照片，或在下方的"演示人脸素材"里点一张（7 种情绪 × 3 张写实照片）。 图片模式下会做单帧识别，结果最稳定，适合演示和算法对照。若低精度下漏检，会自动升到「精确」重试一次。
  2. 视频：选择本地 mp4 / webm 视频文件，程序逐帧检测并叠加情绪标签，可拖动进度条观察情绪变化。
  3. 实时摄像头：点"开启摄像头"，浏览器会请求权限。程序以约 20 FPS 持续检测（单帧推理约 20 ms， 程序按 22 FPS 上限节流，避免推理排队），情绪标签经过 EMA 平滑，不会频繁跳动。
  4. 屏幕视频：点"共享屏幕"，选择一个窗口或整个屏幕（可以用来识别视频会议、播放器里的人脸）。

界面控件说明

  • 检测精度：极速 160 / 均衡 224 / 精确 320（TinyFaceDetector 输入尺寸）。数值越大越准，但更慢。
  • 平滑：EMA 的 α。强（0.15）切换慢、最稳；弱（0.6）反应快、可能抖动。
  • 推荐策略：情绪匹配 / 舒缓调节 / 提振精神，见"算法说明 → 推荐策略"。
  • 在线歌曲库：调用 iTunes Search API 检索，点"分析"会下载 30 秒试听并本地跑旋律情绪算法， 点"+ 推荐"把它加入推荐候选池。在线结果默认只做元数据先验（标记"未分析"）。

常见问题

Q: 摄像头打不开？ 需要 https 或 localhost 环境；若用 IP 访问，Chrome 会禁用 getUserMedia。

Q: 屏幕共享没有画面？ 部分浏览器要求先点击页面再共享；共享时选择"整个屏幕"而不是单个标签页更容易捕获视频。

Q: 在线搜索没结果？ iTunes Search API 在部分网络环境不可达，不影响本地曲库与识别。

Q: 图片识别不出人脸？ 请使用正脸、光线均匀、人脸占比大于画面 20% 的照片；侧脸和遮罩会影响检测。

Q: 我的人脸/音频会被上传吗？ 不会。检测与音频分析全部在浏览器本地完成（TensorFlow.js + Web Audio），只有"在线搜索"会向 iTunes 发请求。

关于演示人脸与曲库

演示用的 21 张人脸由 AI 生成（7 种情绪 × 3 位不同人物，写实人像风格），仅用于本系统的功能演示， 不对应任何真实人物。若用于公开发布，建议替换为你自己拍摄的素材或获得授权的图片。

本地 15 首曲目由 scripts/gen_music.py 以加法合成方式程序化生成 （大调/小调、BPM、失真度、半音簇等参数按情绪设计），因此不涉及任何第三方版权； 每首的"标注情绪"是人类设定的 ground truth，用于验证旋律情绪算法的准确率。
